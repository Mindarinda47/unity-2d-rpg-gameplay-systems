# Problem Solving

## 1. 공격 경계에서 적 상태가 반복 전환되는 현상

### 문제

적과 플레이어의 거리가 공격 범위 경계에 걸리면 추적과 공격 상태가 짧은 간격으로 반복될 수 있었습니다. 하나의 거리값으로 두 방향의 전환을 모두 판단하면 작은 위치 변화만으로 상태가 뒤집히기 때문입니다.

### 판단

공격 시작 조건과 공격을 포기하는 조건을 분리하면 경계에 완충 구간을 만들 수 있다고 판단했습니다. 별도의 상태 구조를 도입하기보다 기존 거리 기반 로직 안에서 전환 조건만 명확히 하는 방법을 선택했습니다.

### 해결

- `attackRange`: 추적 상태에서 공격 상태로 진입하는 거리
- `attackExitRange`: 공격 상태에서 추적 상태로 돌아가는 거리
- `attackExitRange`가 더 크도록 보정해 두 경계 사이에 히스테리시스 구간 구성
- 넉백과 사망 중에는 일반 추적·공격 갱신 중단

대표 코드: [EnemyAI.cs](../Assets/Scripts/Enemy/EnemyAI.cs)

### 검증

플레이어가 공격 범위 경계를 오갈 때 진입과 이탈이 서로 다른 지점에서 발생하는지, 공격 상태가 불필요하게 반복되지 않는지 확인했습니다. 넉백 종료 후 정상 상태 흐름으로 복귀하는지도 함께 확인했습니다.

## 2. 불러오기 이후 퀘스트 UI가 이전 상태를 유지하는 현상

### 문제

저장된 퀘스트의 상태와 진행도는 복원되지만, 값을 직접 대입하는 것만으로는 기존 이벤트 구독 UI가 변경 사실을 알 수 없었습니다. 런타임 데이터와 화면 표시가 달라질 수 있는 구조였습니다.

### 판단

UI가 저장 시스템을 직접 조회하게 만들면 시스템 간 의존성이 커집니다. 평상시 퀘스트 변경과 동일한 알림 경로를 복원 과정에서도 사용하는 편이 일관된다고 판단했습니다.

### 해결

1. `SaveManager`가 저장된 `questId`로 퀘스트를 조회합니다.
2. `QuestManager.LoadQuestState`가 상태와 진행도를 복원합니다.
3. 복원 성공 후 상태 변경·진행도 변경 이벤트를 다시 발행합니다.
4. 퀘스트 UI는 기존 구독 경로에서 최신 값을 반영합니다.

대표 코드: [SaveManager.cs](../Assets/Scripts/Manager/SaveManager.cs), [QuestManager.cs](../Assets/Scripts/Manager/QuestManager.cs)

### 검증

서로 다른 퀘스트 상태와 진행도를 저장한 뒤 불러와 런타임 값과 추적 UI가 함께 갱신되는 흐름을 확인했습니다.

## 3. 손상되거나 일부 항목이 누락된 저장 데이터 처리

### 문제

파일 접근 실패, 잘못된 JSON, null 목록, 현재 데이터베이스에 없는 아이템·퀘스트 ID가 들어오면 예외가 전파되거나 복원 과정이 중간에 멈출 수 있었습니다.

### 판단

저장 형식을 바꾸거나 복잡한 복구 계층을 추가하기보다, 실제 파일과 런타임 데이터가 만나는 경계에서 최소한의 방어를 적용했습니다. 저장 데이터의 필수 구조가 유효하지 않으면 복원을 중단하고, 목록 자체가 존재할 때는 잘못된 개별 항목만 제외하는 기준을 사용했습니다.

### 해결

- 파일 읽기·쓰기와 JSON 역직렬화 실패 처리
- 역직렬화 결과가 null이거나 인벤토리·퀘스트 목록이 null이면 전체 복원 중단
- 필수 매니저와 `ItemDatabase`가 없을 때 저장·불러오기 중단
- 목록이 존재하는 경우 비어 있거나 등록되지 않은 `itemId`, `questId`는 경고를 남기고 해당 항목만 건너뜀
- 정상적으로 복원 가능한 나머지 항목은 기존 저장 형식과 복원 순서를 유지

대표 코드: [SaveManager.cs](../Assets/Scripts/Manager/SaveManager.cs)

### 검증

정상 저장 데이터가 기존 구조로 복원되는 경로와 함께, 파일 부재·잘못된 JSON에서는 안전하게 종료되고 필수 목록이 null이면 복원 전체를 중단하는 흐름을 확인했습니다. 목록이 유효한 상태에서 비어 있거나 등록되지 않은 ID는 해당 항목만 제외하고 나머지 항목을 계속 처리하는지도 대조했습니다.
